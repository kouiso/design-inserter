## §B. UX Review Panel — 10 persona による批評

各 persona の最大級の指摘 + 推奨アクション。複数 persona が同じテーマを挙げた箇所が **収束テーマ** = 優先度 P1。

### Dieter Rams — "Less but better"

> 設定画面 (`admin.php`) には「パーツ数 / ソース URL / shortcode」の 3 行が並ぶだけだが、これは情報過多ではなく **情報不足**。販売プロダクトであれば本質は「ユーザは今ここで何ができるのか」。今の画面はそれを示していない。
> Recommendation: 設定ページを「222 パーツを今すぐブラウズする → エディタへ」「データ更新日」「サポート連絡先」の 3 ブロックに削ぎ落とす。装飾ではなく機能の最小集合に。

### Don Norman — Affordance / Mapping

> Picker の入れ子スクロール (C-05) は **mapping の失敗**。サイドバーは縦スクロール、その中の grid も縦スクロール、その上の cats も縦スクロール — ユーザの mental model「サイドバー = 1 スクロール領域」と一致しない。タッチパッド慣性スクロールでカテゴリと grid を行き来する事故が起きる。
> Recommendation: スクロール領域は親 (Inspector) 1 つに統一。grid と cats の max-height を全削除。

### Jakob Nielsen — 10 heuristics

> H1 (Visibility of system status) と H9 (Help users recover from errors) が同時に壊れている (C-03)。fetch 失敗時にユーザに何が起きたのか伝わらず、回復経路もない。これは販売プロダクトとして「あるはずのものが無い」レベル。
> Recommendation: エラー Notice + retry ボタンの実装は最優先 v0.3 の Must。

### Steve Krug — "Don't make me think"

> Picker で `「全て (222)」` を選んだのに 40 件しか出ない (C-01) は典型的な "make me think" の罠。ユーザは「あれ、表示されてない 182 件はどこ?」を考えなくてはいけない。
> Recommendation: 222 件全部見せる。サムネ 60px なら 222 件でも 2 カラム×111 行 = 縦 6,660px 程度、入れ子スクロール撤去 (C-05) と同時に親スクロールに乗せれば許容範囲。

### Luke Wroblewski — Mobile-first / Form

> WordPress 管理画面はモバイルでも使われる (出張先での記事修正等)。現在の `.di-picker__cats` flex-wrap + 入れ子スクロールはスマホ 375px で完全に壊れる。タッチ 44pt 規格 (M-09 関連) も 24px button では未達。
> Recommendation: モバイル幅で picker を bottom sheet 風に切替。カテゴリは `<select>` に縮約。

### Frank Chimero — Editorial taste / Typography

> 11px / 10px / 12px / 13px の混在 (M-02) は **文字を「データ」として扱っているサイン**。サイズの選択にエディタとしての意図がない。Gutenberg 標準 13px に揃え、補助情報のみ 12px、強調のみ 14px の 3 段階で十分。
> Recommendation: タイポグラフィスケール 12/13/14 に固定、px ハードコードを変数化。

### Susan Weinschenk — Cognitive psychology

> 28 カテゴリ × 222 パーツの組み合わせは **Hick's law** の典型ケース。選択肢 28 個の中から「見出し」を選ぶ時間は対数的に増える。max-height 140px の入れ子スクロールはこの認知負荷を更に増やす。
> Recommendation: カテゴリを上位 5-7 個 (見出し / ボタン / ボックス / リスト / フォーム / その他) にグルーピング。28 個全表示は accordion 内に。

### Erika Hall — Conversation design

> エラーコピー「該当するパーツがありません」は会話が途切れている (C-06)。「該当するパーツがありません。検索 / カテゴリを **クリア** するか、別のキーワードを試してみてください」のように次の一手を提示すべき。LivePreview の空状態「サイドバーから...選択してください」も同じ問題 (case: ネットワーク失敗時にこの文言が出る → 嘘になる)。
> Recommendation: コピーガイドラインの導入。Empty / Loading / Error 3 状態をそれぞれ独立に文言設計。

### Brad Frost — Atomic design / Reusable components

> `PartCard` / `PartPicker` / `LivePreview` はインライン定義され、ファイル外から再利用不可。今後「shortcode picker (TinyMCE)」「メタボックス」等で同じ Picker を出したい場合 全部 再実装になる。
> Recommendation: editor.js を ESM 化 (L-01) → 各 component を export → 別 entry から import 可能に。

### Cheryl Platz — Multi-modal / Failure handling

> Modal パーツ (`enhanceModal` in frontend.js:205) の挙動: Esc キーで閉じる対応はあるが、open trigger と close trigger が CSS の `:checked` 状態に依存。JavaScript 無効環境では Modal が開きっぱなしになるリスク。failure handling として `<noscript>` での fallback メッセージが無い。
> Recommendation: JS 無効環境では `display: none` で modal トリガー自体を隠す `<noscript>` ブロックの追加。
